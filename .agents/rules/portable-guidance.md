# Portable project guidance

Canonical behavior lives in .agents, independent of a specific editor. Keep project paths, stack, commands, and product conventions in the project profile. Keep domain constraints in narrowly named rules/skills.

Each skill is a folder with SKILL.md, YAML name and description, and only the workflow details that affect decisions. Link substantial reference material instead of duplicating it.

IDE adapters route to the canonical files. Preserve existing adapter settings and metadata. Do not copy competing rule bodies into multiple editors, claim universal discovery, or invent capabilities.

When moving to a new project, update the project profile and review all domain-specific skills. Generic guidance must not imply permissions, override user instructions, or mandate unavailable tools. Validate references after moves.
